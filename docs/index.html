The system

Think. Act. Prove. Learn.

Beast is not only a knowledge system. It turns proven knowledge into execution-ready work for an authorized, compatible Data 360 org.

  1. Think. Use preflight, phase routing, sf-docs, OpenAPI, Beast skills, proof ledger, and sf-skills companion guidance to decide the safe path.
  2. Act. Use MCPs, APIs, CLI commands, metadata tools, or helper scripts only after org, data space, permissions, tools, and approval are clear.
  3. Prove. Read back IDs, status, counts, metadata, query results, logs, events, or delivery signals before calling the work done.
  4. Learn. Promote only clean reusable lessons into Beast, and keep scenario-heavy experiments in Labs until they are distilled.
Think with Beast, docs, OpenAPI, and skills Act with MCPs, APIs, and CLI Prove with readback Learn through Labs and the proof ledger

Proof ledger

The schema told us what was possible. The proof ledger records what actually worked.

The ledger records promoted evidence and caveats from authorized lab work. It does not claim that every connector, activation destination, search index, semantic model, or deployment path has been proven in every target org.

Live-tested

  • Data spaces and metadata
  • Query SQL and Profile API
  • DBT segment create/read/count
  • Data action target and action create
  • Activation target create/read
  • Search index and calculated insight list

Captured gotchas

  • includeDbt.models.models[] is the working DBT segment create shape.
  • Readback normalizes DBT models to includeDbt.models[].
  • Approximate segment count can fail when the feature is disabled.
  • Segment members use a delta window; status/count readback is primary proof.
  • Activation target readback was reliable by returned ID.
