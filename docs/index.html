Operating loop

No guessing. No doc dump. Proof first.

Every Data 360 task now follows the same high-signal loop. It is simple enough to repeat and strict enough to catch bad assumptions.

  1. Classify the phase and load the right specialist skill.
  2. Fetch official Salesforce docs when behavior, limits, or setup matter.
  3. Search the OpenAPI catalog for method, path, params, and schemas.
  4. Use the live-tested API cookbook before writing payloads.
  5. Validate in the org with status fields, counts, metadata, and readback.
  6. Document the proof and the caveat, not just the happy path.

API cookbook

The useful truth came from testing.

OpenAPI gave structure. The lab gave judgment. The cookbook now captures the patterns that would otherwise cost hours in customer work.

Live-tested surfaces

Data spaces, metadata, Query SQL, Profile API, segments, segment count, data action targets, data actions, activation targets, search-index list, and calculated-insight list.

Hard-won API lessons

DBT segment create needs includeDbt.models.models[]; approximate counts can fail by feature flag; segment members use a delta window; activation target readback is safest by ID.

Safer customer behavior

Payloads are built from catalog, checked against docs, tested with explicit data space context, then proven by readback.
